## 一、系统架构简介

Omnigent 是一个**多角色、多用户的 AI 团队协作平台**：

```
┌─────────────────────────────────────────────────┐
│  192.168.10.20:8000（服务器，中央协调）           │
│  ├─ 账号系统（Postgres：/data/postgres）          │
│  ├─ 项目/任务/流程管理                            │
│  ├─ 技能中心                                    │
│  └─ 会话协调                                    │
└──────────────┬──────────────────────────────────┘
               │ WS 隧道连接
    ┌──────────┼──────────┐
    ▼          ▼          ▼
 Host A      Host B     Host C（执行机，跑 AI 任务）
```

### 三个角色
| 角色 | 说明 | 需要安装 |
|------|------|---------|
| **管理员** | 建账号、管项目、分配任务 | 浏览器 |
| **团队成员** | 认领/执行/验收任务 | 浏览器 |
| **执行机（Host）** | 真正跑 AI 的机器 | CLI 或 Docker |

## 二、安装指南

### 2.1 普通用户（浏览器，零安装）

**什么都不用装**——浏览器打开：

```
http://192.168.10.20:8000
```

用管理员分配的账号登录即可。

### 2.2 桌面端（Windows）

**安装包**：`Omnigent Setup 0.9.1.exe`

1. 双击安装包
2. 安装向导中**可选择安装路径**
3. 安装完成，桌面出现 **Omnigent** 图标

### 2.3 执行机（Host）安装

**方式 A：本机 CLI（Windows）**

前置：Python 3.12+、Git、uv 或 pip

```powershell
# 1. 安装 uv（首次）
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"

# 2. 安装 omnigent CLI（从公司仓库，含全部修复）
uv tool install --python 3.12 "git+https://github.com/remexs/omnigent.git@remexs/zh-ui"

# 3. 验证
omnigent --version
# 应显示：omnigent 0.9.0 (9777132f, ...)
```

没有 uv 用 pip：
```powershell
pip install "omnigent"
```

**方式 B：Docker（免安装，推荐服务器用）**

```bash
docker run -d --name omnigent-host-你的名字 \
  ghcr.io/omnigent-ai/omnigent-host:latest \
  omnigent host --server http://192.168.10.20:8000
```

> host 镜像已内置 omnigent CLI + 全部执行环境（git/tmux/pi 等）。

## 三、连接与登录

### 3.1 桌面端首次连接

1. 打开 Omnigent 桌面端
2. 连接页面输入服务器地址：
   ```
   http://192.168.10.20:8000
   ```
   （**端口是 8000**，别填错）
3. 点「连接」

### 3.2 首次登录

| 账号 | 密码 | 角色 |
|------|------|------|
| root | 123456 | 管理员（内置）|
| （其他成员）| 管理员分配 | 团队成员 |

> 密码至少 **8 位**（服务器要求）。

### 3.3 桌面端 CLI 配置（关键！）

桌面端需要知道 omnigent CLI 在哪，才能「本地启动」/「注册为执行机」：

1. 桌面端**连接页面** → 右上角**设置齿轮** ⚙️
2. 「Path to the Omnigent CLI」填：
   ```
   C:\Users\你的用户名\.local\bin\omnigent.exe
   ```
3. 点「Done」
4. 验证：设置 → 本地 CLI → 应显示 `Found · omnigent 0.9.0`

> **注意**：此路径**只能从连接页面设置**（安全设计——防止已连接的服务器把应用指向其他二进制）。设置页的路径是只读显示。

## 四、账号管理（管理员）

### 4.1 创建新用户

1. 用 root 登录 → 设置 → **成员**
2. 点「添加成员」
3. 输入用户名 + 密码（≥8 位）
4. 保存——用户即可登录

### 4.2 邀请注册（可选）

管理员生成邀请链接 → 用户自己设置密码：
1. root 登录 → 设置 → 成员 → 生成邀请
2. 把注册链接发给用户
3. 用户浏览器打开 → 设置密码 → 完成注册

### 4.3 角色权限
- **root**：管理员（is_admin=true）——全部权限
- **普通成员**：认领/执行/验收任务、查看项目

## 五、团队协作使用

### 5.1 创建项目（管理员/项目经理）

1. 侧边栏 → **项目** → 新建团队项目
2. 填：
   - **项目名称**（如「电商协作平台」）
   - **成员**（从 host 池勾选参与成员）
   - **项目级 YAML**（可选，任务工作流模板）
3. 创建后可在「项目设置」配置：
   - **默认工作目录**（新任务预填）
   - **默认主机**
   - **项目记忆**（跨会话经验，播种到每个任务）
   - **项目上下文**（指令/文档，注入每个任务）

### 5.2 添加任务

1. 项目 → 流程列表 → 添加任务
2. 填任务标题 + **工作流 YAML**（步骤链）：
   ```yaml
   workflow:
     steps:
       - id: requirement
         name: 需求分析
         agent: zhangsan-agent
         auto_approve: true
       - id: development
         name: 开发
         agent: wangwu-agent
         depends_on: [requirement]
   ```
3. 保存 → 自动生成任务树（主任务 + 子任务）

### 5.3 任务执行流程（状态全由用户驱动）

```
创建任务 → 认领（Claim）→ 启动（Launch）→ 执行（AI 工作）
        → 提交（Complete）→ 验收（Evaluate）→ 完成
                    ↓ 不合格
                  返工（Returned）
```

| 动作 | 谁做 | 说明 |
|------|------|------|
| **认领** | 团队成员 | 选择要执行的任务 |
| **启动** | 认领人 | 在指定 host 上启动会话 |
| **提交** | 执行人 | 完成任务，写交接文档 |
| **验收** | 项目经理 | 评估通过/返工 |

### 5.4 交接（Handoff）+ 记忆（Memory）

每个任务阶段完成后，AI 必须写：
- `handoff/HANDOFF-<阶段名>.md` — 阶段交接（链式）
- `memory/MEMORY-<主题>.md` / `MEMORY-<日期>.md` — 项目记忆

**交接门禁**：不写交接文档，任务无法提交（强制 AI 完成交接）。

## 六、执行机（Host）配置

### 6.1 注册本机为执行机

**命令行方式**：
```powershell
omnigent host --server http://192.168.10.20:8000
```

**桌面端方式（一键）**：
1. 确认 CLI 已配置（见 3.3）
2. 设置 → 本地 CLI → **「将此机器连接为执行机」**
3. 状态变绿 = 已连接

> 桌面端管理的 host：**关闭桌面端即断线**。

### 6.2 常驻（关终端也在）

**Windows 任务计划程序**（开机自启 + 后台）：
```powershell
# 创建（当前用户、登录自启）
schtasks /create /tn "Omnigent Host" /tr "\"C:\Users\你的用户名\.local\bin\omnigent.exe\" host --server http://192.168.10.20:8000" /sc onlogon /rl HIGHEST /f

# 立即启动
schtasks /run /tn "Omnigent Host"

# 停止
schtasks /end /tn "Omnigent Host"
```

### 6.3 查看主机状态

- Web：设置 → **主机** → 看到所有已注册机器（在线/离线）
- 命令行：`omnigent host status`

### 6.4 停止/卸载 host

```powershell
omnigent host stop --server http://192.168.10.20:8000
# Docker 方式
docker rm -f omnigent-host-你的名字
```

## 七、工作目录配置

### 7.1 默认工作目录

**默认 = `~/.omnigent/workspace`**（host 连接时自动创建）：
```
Windows: C:\Users\你的用户名\.omnigent\workspace
Linux:   /home/你的用户名/.omnigent/workspace
```

### 7.2 选择其他目录

1. 新建会话 → 主机选择器 → 点工作目录
2. **输入任意路径**：
   - Windows 盘符：`D:/workspace` 或 `D:\workspace`（支持）
   - Linux：`/data/projects/xxx`
   - 家目录：`~/projects/xxx`
3. 或浏览目录树选择

### 7.3 项目级默认目录

项目设置 → 默认工作目录 → 该项目的所有新任务预填此目录（可覆盖）。

### 7.4 目录要求
- 目录必须**存在**（host 拒绝在缺失目录启动）
- 所有 host 建议**共享同一目录**（交接文件才能互通）

## 八、技能中心

### 8.1 浏览技能
设置 → **技能** → 从 SkillHub 注册中心浏览/搜索

### 8.2 安装技能
1. 点「安装技能」
2. 搜索技能 → 选择
3. 选目标（agent bundle 或全局）
4. 安装

### 8.3 技能中心地址（可配置）
- 默认：`http://192.168.10.86:4011`（服务器配置）
- 管理员可通过环境变量 `OMNIGENT_SKILL_REGISTRY` 覆盖
- 安装对话框可临时指定其他地址

### 8.4 本地技能（自动加载）
项目自带技能（如交接约定、代码评审）在：
```
deploy/docker/host-configs/skills/<名称>/SKILL.md
```
自动打包进所有 agent 会话，无需手动安装。

## 九、常见问题（FAQ）

### Q1: 登录报「invalid username or password」？
- 确认用户名密码正确（密码 ≥8 位）
- 找管理员确认账号已创建

### Q2: 连接服务器后「没有主机」？
- 说明没有 host 注册——按「第六节」配置一台执行机

### Q3: 桌面端报「未找到 Omnigent CLI」？
- 按 3.3 在**连接页面**设置 CLI 路径

### Q4: 桌面端报「timed out waiting for host to connect」？
- 旧版 CLI 的 Windows 编码 bug——**更新 CLI**（见 2.3 方式 A）
- 确认服务器在线（浏览器能打开）

### Q5: 想选 D 盘工作目录但不能输入？
- 输入 `D:\workspace` 或 `D:/workspace`（盘符路径已支持）
- 确认目录存在

### Q6: 任务提交被拒（交接门禁）？
- AI 必须写 `handoff/HANDOFF-<阶段>.md` + `memory/MEMORY-*.md`
- 补写后重试

### Q7: host 关终端就离线？
- 用桌面端按钮（6.1）或任务计划程序常驻（6.2）

## 十、故障排查

### 10.1 服务器状态检查
```bash
# 服务器健康
curl http://192.168.10.20:8000/api/version
# 应返回 {"version":"0.9.0"}

# 服务器容器
ssh root@192.168.10.20 "cd /data/omnigent && docker compose ps"
```

### 10.2 host 日志
```
Windows: C:\Users\你的用户名\.omnigent\logs\host\host-*.log
Linux:   ~/.omnigent/logs/host/host-*.log
```

### 10.3 常见错误速查
| 错误 | 原因 | 解决 |
|------|------|------|
| HTTP 403 注册 host | 身份未授权 | 用管理员分配的 host 账号 |
| 'gbk' codec 错误 | 旧 CLI Windows bug | 更新 CLI 到 0.9.0 (9777132f) |
| workspace 不存在 | 目录缺失 | 建目录或换存在的目录 |
| 找不到 CLI | 未配置路径 | 连接页面设置路径 |
