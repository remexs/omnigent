# Omnigent 多角色协作平台 — 测试流程设计（展示版）

> **方法论**：全部操作基于真实浏览器（agent-browser 可见窗口），
> 观察页面真实反应；后端 API 验证通过不算数。

---

## 一、角色与职责

| 角色 | 用户 | 核心职责 |
|------|------|---------|
| **项目经理** | admin | 建项目、配置成员/角色/流程、AI 拆分子任务、分派、监控、评价、重分配 |
| **项目成员** | zhangsan / wangwu / zhaoliu / lisi | 领取自己的子任务、调自己的 agent 执行、提交、评价主任务 |
| **Agent** | 各成员自己的 pi | 按项目上下文执行任务；admin 的 agent 负责需求拆分 |

---

## 二、可见性与操作总原则

```
【可见性】项目经理 + 所有项目成员
  ✅ 看到所有任务：主任务（进度条）+ 全部子任务 + 各自状态/进度
  ✅ 任何人可见所有任务进度（透明协作）

【操作】只限自己的
  ✅ 领取：只能领取【被分配给自己】的子任务
  ✅ 执行：只能在自己的 host 上执行【自己领取】的任务
  ❌ 主任务：成员不可领取/执行（归项目经理）
  ❌ 别人的子任务：不可领取/执行（只能看）
  ✅ 分配/重分配/评价产物：仅项目经理 admin
```

## 三、权限矩阵（职责不越权）

| 操作 | 主任务（根） | 子任务（阶段） |
|------|-------------|---------------|
| 创建 | ✅ 仅项目经理 admin | ✅ 仅项目经理 admin |
| 分配（指定 assignee）| —（无执行者，聚合容器）| ✅ 仅项目经理 admin |
| 领取 | ❌ 成员不可领取；✅ 仅 admin 可管理 | ✅ 仅被分配的成员 |
| 执行（启动 agent）| ❌ 不执行（无 agent 绑定）| ✅ 仅 assignee 在自己 host |
| 确认完成 | —（主任务：✅ 仅 admin 确认）| ✅ 仅领取者自己确认完成 |
| 评价产物 | —（子任务评价在各自任务）| ✅ 项目经理 admin 评审 |
| 评价主任务（分配合理性）| ✅ 项目成员可评价/拒绝分配 | — |
| 重新分配 | ✅ 仅 admin | ✅ 仅 admin |
| 查看 | ✅ 项目经理+成员全可见 | ✅ 项目经理+成员全可见（所有人可见所有任务进度）|
| 领取 | ❌ 成员不可领（仅 admin 管理）| ✅ 仅被分配的成员（只能领自己的）|
| 执行 | ❌ 不执行 | ✅ 仅 assignee（只能执行自己的）|
| **进度** | ✅ 自动 = 子任务完成度百分比 | 各自状态 |

### 主任务进度条 + 项目经理确认完成
```
主任务进度 % = (completed 子任务数 / 子任务总数) × 100
显示：进度条 + 百分比 + 各阶段色块（绿=完成/琥珀=进行中/灰=未开始）

【完成确认机制】
  ├─ 子任务：由【各自的领取者】确认完成（领取者执行完 → 提交确认 → completed）
  └─ 主任务：所有子任务完成后 → 主任务进入"待项目经理确认" →
             项目经理确认 → completed（不自动完成，人工把关）
```

### 确认责任（谁确认谁）
| 任务 | 完成确认人 | 动作 |
|------|-----------|------|
| 子任务 | 各自的领取者（执行者）| 执行完点【确认完成/提交】|
| 主任务 | 项目经理（admin）| 所有子任务完成后，admin 确认 → completed |

### 子任务完成模式（可配置）
```
每个子任务可配置完成方式（默认手动，项目/任务级可设自动）：
  ├─ 【手动】领取者领取 → 手动启动 agent → 执行完手动点【确认完成】
  └─ 【自动】领取者领取 → 自动启动 agent → agent 执行完【自动确认完成】
       （组员自己配置，或由配置的 agent 代完成，无需人工介入）

配置位置：
  - 项目流程模板 phases[].mode = "auto" | "manual"（默认 manual）
  - 或子任务创建时指定 auto_complete
  - 领取者也可对已领取任务切换模式
```

### 自动完成流程（mode=auto）
```
领取（assignee 确认）→ 自动 launch 到自己的 host
  → agent 执行 → 完成 → 自动确认（任务 → completed）
  → 主任务进度更新
全程无需人工点【提交/确认】
```

### 展示形式：看板任务卡片树（当前已满足，不改）
```
当前看板即任务卡片树：
  - 按状态分列（待办/进行中/待评价/已完成/打回/阻塞）
  - 卡片内展示任务树层级（根任务含进度条，子任务缩进）
  - 每卡片：状态/领取者/执行host/产物/评价

【任务 ↔ 会话跳转】（新增）
  - 每个任务卡片提供【查看会话】入口（有 session_id 时）
  - 项目经理需求分析会话 → 点击定位到自己的对话
  - 组员任务执行会话 → 点击定位到自己的对话记录
  - 跳转到 /c/{session_id} 打开会话页
```

### 会话归属（数据隔离）
```
【任务会话】必须挂在项目下：
  - job launch 创建会话时，conversation.project_id = 任务所属项目
  - 项目成员可见该项目下所有任务会话（协作透明）
  - 会话列表按"项目会话 vs 个人会话"区分

【私有会话】保持独立：
  - 个人非项目会话（project_id = NULL）仅 owner 可见
  - 与任务/项目无关，不受项目成员可见性影响
```

### 越权防护（后端校验）
- claim 校验：子任务 assignee≠自己 → 403；主任务成员 claim → 403
- launch 校验：非 assignee / 非 host owner → 403
- evaluate 产物：非 admin → 403（成员只能评价主任务分配，不能评价产物）
- reassign：非 admin → 403

## 六、执行策略（确认后执行）

```
严格按 阶段1→7 顺序，每步用 agent-browser 真实操作
┌─ 每阶段结束：观察页面 + 截图留证
├─ 任一 UI 操作失败：记录为 bug（不跳过，不 API 绕过）
├─ AI 拆分（2.2-2.5）：若 agent 空回复（已知 harness 问题）
│   则先修 harness，再重跑该步骤
└─ 全部通过后：汇总测试报告
```

## 七、关键判定标准

1. **UI 可操作**：每个按钮/表单真实可点击填写，页面有反应
2. **权限正确**：只能领自己的、admin 能看不能执行别人 host、非成员隔离
3. **流程闭环**：建项目→AI 拆分→分配→领取→执行→提交→评价→重分配 全通
4. **可见性**：主任务+所有任务可看、会话按归属隔离
